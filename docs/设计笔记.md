### 单词回顾 + 单词本（决策 9、10）

**用户的原始描述**：
> 错题回炉旁边增加一个「单词回顾」，这个单词回顾是和上面的单词背诵相关联的。
> 每日我会导入我新背会的单词，第二天进行回顾。

**理解**：这是一个和「错题双段回炉」结构类似的机制 ——
每天把新背的单词录入（导入），次日生成回顾任务。

**待确认的设计细节**：

- [ ] **单词的数据结构**：只要拼写？还是「单词 + 释义 + 例句」？
- [ ] **导入方式**（关键，影响工作量）：
  - A. 手动逐条输入（简单，但每天录几十个词很累）
  - B. 批量粘贴文本（一行一个词，最快）
  - C. 从文件导入（txt / csv）
  - D. 拍照 OCR（工作量大，不建议）
- [ ] **回顾节奏**：只「次日回顾一次」？还是像错题那样两段（次日 → +7 天）？
- [ ] **回顾交互**：只看一遍打勾？还是做「遮住释义自测」？（后者更有效但要做卡片翻转式 UI）
- [ ] **与课表单词块的关系**：07:20 的「英语单词背诵」时段，是否就是「导入新单词」的动作点？
- [ ] **数据量上限**：一天 100 词的话，一周 700 词，列表要怎么组织（按日期分组？按掌握状态？）

**行动卡布局：已定 —— 三张并列**（用户 2026-11-02 明确要求）

```
┌──────────┬──────────┬──────────┐
│ 今日事项  │ 错题回炉  │ 单词回顾  │
│ 1/9 段   │ 0 题     │ 0 词     │
│ 07:20 ›  │ 已清空    │ 已清空    │
└──────────┴──────────┴──────────┘
```

**尺寸核算**（iPhone 15/16，屏宽 393pt）：
- 卡内容宽度 = 393 − 16×2（页面边距）− 8×2（两张间隙）= **345pt**
- 每张开 ≈ **115pt**，减去内部 padding 12×2 → **内容宽约 91pt**

**风险点（实现时要处理）**：

| 元素 | 现状 | 三张并排后会怎样 |
|---|---|---|
| 标题「今日事项 / 错题回炉 / 单词回顾」 | 12pt，4 字 | 约 48pt，**放得下** ✓ |
| 数值「1/9 段」「0 题」「0 词」 | 20pt rounded | 最长「0/11 段」约 74pt，**偏紧**，需要 `minimumScaleFactor` |
| 提示行「下一项 07:20 ›」 | 11pt | 约 68pt + 箭头，**要缩短**成「07:20」或省略箭头 |
| 数值到两位数（如 100 词） | — | 「100 词」约 62pt，可接受 |

**结论**：三张并排可行，但必须做三件事 ——
1. 数值加 `minimumScaleFactor(0.7)` + `lineLimit(1)`
2. 提示行缩短（去掉「下一项」前缀，只留时间；或去掉箭头）
3. 标题允许缩到 11pt（`minimumScaleFactor`）

### 掌握程度（决策 14）—— 用分数直观显示

**用户最终要求（2026-11-02）**：
> 我就是想用分数来直观地显示出来。

**所以不要复杂的多档标签，就显示一个分数。**

**形态**：

```
数学 · 函数、极限、连续      [ 72 ]
408 · 绪论、线性表            [ 85 ]
英语 · 长难句 + 语法基础      [ 未测 ]
```

**规则**：
- 每个进度项可以记一个 **0–100 的分数**（自测得分 / 真题得分）
- 分数**直接显示成数字**，配颜色区分：
  - `< 60` 红 · `60–79` 橙 · `80–89` 蓝 · `≥ 90` 绿
- **没填分数就显示「未测」**，不显示 0 分（不制造虚假进度）
- 可按科目 / 按轮次算**平均分**，显示在汇总处

**与勾选的关系**：
- 勾选 = 这章「学过了」
- 分数 = 这章「掌握到什么程度」
- 两者独立：可以学过了但没测（勾选 + 未测）

**待确认**：
- [ ] 分数的分母统一按 100 算，还是允许记「对了 18 / 共 25」由系统换算？
- [ ] 同一章可以多次考试（记录多次分数看趋势），还是只保留最新一次？

### 跨设备同步（决策 15）

**用户需求**：iPhone 上记录的内容，希望在别的设备也能看到（用户有小米平板）。

**现实约束**：
1. 小米平板是 **Android**，我们的 App 是 iOS 原生，**装不上** —— 所以「同步到平板」必须有第二种客户端（Web 或 Android）
2. 免费 Apple ID **不能用 iCloud 容器**（需要付费开发者账号）
3. 没有服务器，也没有持续付费预算

**可选方案对比**：

| 方案 | 成本 | 自动程度 | 可行性 |
|---|---|---|---|
| **A. 手动文件同步**（导出 JSON → 网盘 → 另一台导入） | 0 | 手动 | ✅ **现在就能做**（备份/恢复已实现，只差「合并」逻辑） |
| **B. WebDAV 自动同步**（坚果云等免费提供 WebDAV） | 0 | 半自动（打开 App 时同步） | ✅ 中等工作量，需要写 WebDAV 客户端 |
| **C. iCloud Drive** | $99/年 | 全自动 | ❌ 免费账号不支持 |
| **D. 自建服务器** | 有 | 全自动 | ❌ 成本与维护不值 |

**建议路线**：
1. 先做 A（手动导入导出 + 合并），零成本，立刻能用
2. 如果确实嫌手动烦，再做 B（WebDAV）
3. 平板上要真正「能看」，还需要一个 Web 版界面 —— 这是另一个工程

**⚠️ 关键提醒**：B 和 Web 版都属于新工程，不是改界面。建议等当前这些意见做完、App 稳定运行一段时间再评估。

## 一、课表卡改造方案（已确认要做，尚未动工）

### 需求
> 事件太多了。改一下：显示当前事件和下一件事件；点击反转后展示当天全部事件。

### 现状
`TodayView.timetableCard` 一次性渲染全部 8 个时间段，每段「时间一行 + 标题一行」，
工作日占掉半屏多；而且看不出来「现在该做哪一段」。

### 目标形态

**正面（默认）**

```
┌────────────────────────────────────┐
│ 今日课表          已完成 0/8 段    ◯0%│
│                                    │
│ 12:00  ┃ 午餐 + 午休（30 分钟）     │
│ 14:00  ┃ 进行中                    │
│                                    │
│ 14:00  ┃ 408（3.5 小时）      3.5h │
│ 17:30  ┃ 接下来                    │
│                                    │
│ 点击查看全部 8 段          ⟳        │
└────────────────────────────────────┘
```

**背面**：点一下翻转 → 当天全部 8 段（原来的列表）+ 额外补记 + 右上角「收起」。

### 实现要点

1. **当前时段判定**
   ```swift
   private var currentMinute: Int {
       let c = CalendarHelper.shared.dateComponents([.hour, .minute], from: Date())
       return (c.hour ?? 0) * 60 + (c.minute ?? 0)
   }
   private var currentBlock: ScheduleBlock? {
       blocks.first { currentMinute >= $0.startMinute && currentMinute < $0.endMinute }
   }
   private var nextBlock: ScheduleBlock? {
       if let cur = currentBlock {
           return blocks.first { $0.startMinute >= cur.endMinute }
       }
       return blocks.first { $0.startMinute >= currentMinute }
   }
   ```

2. **复用 FlipCard**（`DesignSystem/FlipCard.swift`，阶段卡已经在用）

   ⚠️ **关键坑**：FlipCard 现在对整个内容加了 `.onTapGesture { toggle() }`。
   如果背面有可点的行（课表打勾），点行会连带触发翻面。
   改法：**手势只在正面生效**，背面由调用方放一个「收起」按钮翻回来。

   ```swift
   .onTapGesture {
       if !showingBack { toggle() }
   }
   ```
   阶段卡的背面也要补一个「收起」入口（现在背面没内容可点，但改完后点背面不再翻回）。

3. **截图验证**
   加调试参数 `--flip-timetable`，让 CI 能截到背面；正面用现有 `01-today.png`。

### 三个边界情况
- 时间早于第一段 → 无「当前」，只显示「下一件」= 第一段
- 时间晚于最后一段 → 显示「今天的课表已全部结束」
- 周日（休息课表只有 3 段）→ 逻辑相同，不用特判
